# 经验

- 用户明确要求先从模板解决分镜分屏时，先核对结构化与纯文本请求的共同模板入口；把未来脚本写作约束和已有脚本重生时的最终提示词约束分开，避免擅自扩大到生成代码或质量门。
- 模板加了单画面约束后若重生仍分屏，要核对目标分镜的实际版本、最终提示词和参考图顺序；已有 Scene 的上下分区描述不会被新写作指引改写，且上一分镜参考图可能被模型复用成独立画面。不能把模板发布成功等同于出图问题已解决。
- 用户要求验证“模板自动改”时，固定原始已保存 Scene 和参考图作为输入；手动改 Scene 后出图成功只证明该镜头的提示词可改善，不能计作全局模板生效。记录模板版本、相同输入和新图结果。
- 用户要求快速迭代提示词模板时，在本机渲染模板，直接用固定的原始输入和真实模型测试；测试通过后才做一次最终部署，避免每版模板都完整发布。

- 用户要求保留本地模型的审核边界时，推荐升级前必须核实候选型号是否公开可自托管权重、实际部署路径及供应商输入输出审核；不能把同系列托管 API 当作本地无审查模型的直接升级。

- 用户明确依赖分镜保持小说生视频的人物一致性时，优先查分镜模式能否传首帧和角色声音，不能因参考生视频试跑成功就建议更换生成模式；先核对用户实际项目和线上端点能力。

- 用户给出外部讨论（ChatGPT 分享链接等）要求落地时，先按时间顺序读到对话最后的结论，确认执行的是最终方案而非早期设想；用户要的是能解决实际故障的决策和最小动作，不要先产出测试矩阵和大量验收文档。

- 用户说实验文档看不懂时，入口先用普通话说明用途、已完成和未完成的能力，再给命令、术语及审核记录；检查样例链接是否在当前工作区真实存在，别把工程试跑素材写成已验收的真实样本。

- 用户要求“提交 push”且希望在 `main` 找到结果时，应先核对目标分支并推送到用户期望的 `main`；不能只推功能分支后称交付完成。推送后核对远端 `main` 的提交哈希。

- 用户指出网关有日志时，先按任务 ID、TID 和生成时间检索网关及上游日志，再判断最终提示词或工作流是否可追溯；不能仅凭任务表不存 graph、上游 history 为空就断言缺少证据。

- 用户指出 OpenClaw 把内容拒绝显示为登录失败时，应追查 HTTP 错误分类和认证冷却的共同入口，修复机制并验证内容拒绝与真实凭据失效两种路径；不能只建议新开会话。
- 用户要求将 ArcReel Agent 切至已接入的文本模型时，先区分 Agent 的 Anthropic Messages 凭证与普通文本任务的 OpenAI Chat Completions 供应商；探测真实 `/v1/messages` 与工具调用能力后再切换生效凭证。
- 用户明确要求彻底接入新 Agent 模型时，真实验收失败后的临时恢复只用于保护现有会话；必须继续修复调用链、再次切换并完成新会话验收，不能把恢复当作最终交付。
- 用户确认迁移并明确要求本机彻底卸载且不留备份时，及时终止进行中的归档，连同既有专属备份清理；保留与卸载无关的学习资料和项目源码。
- 用户指明页面已在 Orca 浏览器打开时，先用 `orca tab list` 和当前标签页检查实际界面；不要另开浏览器，也不要仅凭 HTTP 返回的 HTML 判断运行后的页面状态。
- 用户明确要求部署本地最新代码时，按当前本地版本规划完整发布；不要自行收窄为只替换某个线上文件。
- 已告知运行中任务会被中断后，用户再次明确要求直接部署，就按该授权完成备份与切换；若用户说明会手动验证，自动检查只覆盖服务与产物完整性。
- 用户要求手动选择多个 OpenClaw 聊天模型时，分别核对账号可用模型、默认模型和 `modelPolicy.allow`；不要把可选列表收窄为默认模型。
- 用户明确指定 ArcReel 项目页时，先核对该应用的供应商、模型目录和可用接口；不要把 OpenClaw 中可选的 OAuth 模型当作 ArcReel 可调用的 API 模型。
- 描述供应商状态时，分别说明“预置入口存在”“已配置凭据”“目标模型在列表中”“调用已验证”，避免把这些状态合成一句含糊的“没有”。
- 用户只要求部署现有代码时，先做当前版本、备份、活动任务与必要构建检查，及时执行发布；不要默认等待耗时的全量闸门。若运行测试，先用项目要求的 Node 版本，避免无效失败拖延部署。
- 用户要求在 ArcReel 的预置供应商页面配置模型时，先确认该入口的认证机制和用户指定的模型是否兼容；不要自行部署独立代理替代用户指定的配置路径。
- 用户将“完整迁移”进一步限定为“服务器安装最新版、仅同步配置”时，以最新范围为准；不要搬运历史会话与 SQLite 状态，重新建立服务端认证并验证。
- 用户明确 Grok 只负责 ArcReel 文本时，区分纯文本与附图的风格分析；不把图像输入失败误判为纯文本接入失败，也不因模型是文本模型就覆盖图片、视频、音频配置。
- 用户要求 ArcReel 直连 OpenClaw 时，撤销不再需要的 llm-modes-gateway 渠道；在保存凭据前核对 OpenClaw 令牌权限与 ArcReel 数据库存储方式。
- 用户明确要求快速修复且不要写测试文件时，立即停止新增测试、撤回本轮测试文件改动；用现有相关测试和真实输入的只读检查快速验证，避免继续扩展测试范围。

## 旧分支记录

# 调试教训

- 服务器版本戳不能证明发布目录与对应 Git 提交逐字一致。基于旧 release 做差量部署时，先对新目录与目标源码做完整文件哈希核验；若发现线上独有的提示词热修，先比对语义并保留有意修改，把例外哈希和发布标识写入记录，避免静默回退角色资产行为。

- 用户要求快速部署时，把构建和验证放在停服之前，停服窗口必须有明确上限。不能关闭网页后无限等待模型生成；先核对 SSE 长连接、任务恢复能力和不可恢复的图片任务，告知中断影响，并按用户最新的恢复服务优先级执行。

- 本项目故障修复不改 ArcReel 代码；用户最终明确允许修改网关、模型、本地 `.env` 和服务器 env。SDK 开关仅在已授权的环境文件中配置；不能把历史请求总 token 当作当前模型固定前缀的实测值。

- 用户报告请求无响应时，原请求自行恢复不等于故障修复。已发现上下文超限、反复压缩与重试，必须继续追踪预算来源、触发阈值和实际计数，在责任层修复并用边界用例验证；将自然恢复与防复发验收分开报告。

- 交付运营手册时，先确认运营的实际内容类型；用户只做小说和剧本 AI 短剧时，以该生产链为主线，不扩写广告、商品或部署教程。

- 提示词契约修复不能等同整条视频链路根治。用户自建 ComfyUI 工作流时，必须把实际提交图、模型家族、编码器/tokenizer、latent/音轨连接及官方提示格式一起核对；只证明新旧图不变，不能证明旧图本来正确。

- 用户要求一次性根因修复时，按上游全部输出格式、素材组合、发声归属和下游全部路由建立契约矩阵；不能以单个成功对白镜头代表覆盖完整。无对白、自由文本附声明、参考语法、能力路由重编译必须分别验证。

- 用户要求先定位解析器时，先确认原文、结构化发声结果和模型实收提示词的边界；未建立责任层证据前，不承诺修复或触发媒体重生成。

- 两行提示词修复也不能无界扩大真实生成矩阵。先估算 GPU 队列与每次实验成本，以用户当前失败片段为主验收；代码测试已通过、有限对照有改善证据时及时收敛，不自动追加跨片/多种子实验。部署状态与媒体质量状态分开报告，不能让排队等待伪装成持续测试。

- 生成原音轨已有异常只能定位到生成端，不能直接推断模型权重缺陷；采样器、参数、运行节点和随机性仍需对照。提示词中的潜在冲突未经单变量验证，不应作为主结论让用户误以为是剧本责任；四步方案应先核对对应作者配置再评价质量。

- 媒体对照样片通过不代表项目当前版本修复。用户反馈新现象时，先锁定当前视频版本、上游 job、实际模型提示词和线上部署状态；字幕抽帧与台词 ASR 分别验收，不能用其中一项替代「动作被朗读」的验证。

- 空上下文 get_context_usage 验证只证明配置传递和计算阈值；不能推导已超限的 resume 历史能自动恢复。用户重启后仍失败时，核对实际 SDK 子进程环境、会话创建时间、失败轮数与压缩事件，区分新会话预防与旧会话恢复。

- 自定义模型窗口不匹配时，先查并实测 SDK 原生 CLAUDE_CODE_MAX_CONTEXT_TOKENS；不能把 AUTO_COMPACT_WINDOW 的最小值当作模型窗口无法下调的证据。通过 get_context_usage 核对 rawMaxTokens、自动压缩状态和阈值后，再判断是否需要源码改造。

- 用户指出提高上下文上限不能解决持续增长时，应先分析每轮新增量、固定工具开销、历史重放与压缩触发条件。扩大容量只能作为临时缓解，不能称为根治；没有增长曲线证据时，不断言指数增长或应用重复注入。

- 用户要求驱动平台测试创作流程时，先排查系统调用与配置，不将任务扩大为代写或生成内容；诊断上下文大小仅提取消息类型、长度、工具 schema 与 token 统计，不读取小说正文。上游 token 超限是症状，取得实际请求构成与计数来源前，不将模型限制差异当作根因。

- 本仓是第三方代码，用户明确要求不改源码。排查错误只在实际责任层调整配置、模型选择、请求适配或网关；不能用应用源码补丁绕过上游故障。本轮误加的源码与测试必须撤回，并让运行服务恢复原版。

- 修改 Agent 凭证后，先区分 HTTP 体检、全新 SDK 请求和已有常驻会话。按 ADR 0017，旧会话保留启动时 env；明确指引用户点击「新建会话」，不要用含糊的「重启会话」让用户误以为刷新或重试能生效。
