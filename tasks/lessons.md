# 经验

- 用户要求“提交 push”且希望在 `main` 找到结果时，应先核对目标分支并推送到用户期望的 `main`；不能只推功能分支后称交付完成。推送后核对远端 `main` 的提交哈希。

- 用户指出网关有日志时，先按任务 ID、TID 和生成时间检索网关及上游日志，再判断最终提示词或工作流是否可追溯；不能仅凭任务表不存 graph、上游 history 为空就断言缺少证据。

- 用户指出 OpenClaw 把内容拒绝显示为登录失败时，应追查 HTTP 错误分类和认证冷却的共同入口，修复机制并验证内容拒绝与真实凭据失效两种路径；不能只建议新开会话。
- 用户要求将 ArcReel Agent 切至已接入的文本模型时，先区分 Agent 的 Anthropic Messages 凭证与普通文本任务的 OpenAI Chat Completions 供应商；探测真实 `/v1/messages` 与工具调用能力后再切换生效凭证。
- 用户明确要求彻底接入新 Agent 模型时，真实验收失败后的临时恢复只用于保护现有会话；必须继续修复调用链、再次切换并完成新会话验收，不能把恢复当作最终交付。
- 用户确认迁移并明确要求本机彻底卸载且不留备份时，及时终止进行中的归档，连同既有专属备份清理；保留与卸载无关的学习资料和项目源码。
- 用户指明页面已在 Orca 浏览器打开时，先用 `orca tab list` 和当前标签页检查实际界面；不要另开浏览器，也不要仅凭 HTTP 返回的 HTML 判断运行后的页面状态。
- 用户明确要求部署本地最新代码时，按当前本地版本规划完整发布；不要自行收窄为只替换某个线上文件。
- 已告知运行中任务会被中断后，用户再次明确要求直接部署，就按该授权完成备份与切换；若用户说明会手动验证，自动检查只覆盖服务与产物完整性。
- 用户要求手动选择多个 OpenClaw 聊天模型时，分别核对账号可用模型、默认模型和 `modelPolicy.allow`；不要把可选列表收窄为默认模型。
- 用户明确指定 ArcReel 项目页时，先核对该应用的供应商、模型目录和可用接口；不要把 OpenClaw 中可选的 OAuth 模型当作 ArcReel 可调用的 API 模型。
- 描述供应商状态时，分别说明“预置入口存在”“已配置凭据”“目标模型在列表中”“调用已验证”，避免把这些状态合成一句含糊的“没有”。
- 用户要求在 ArcReel 的预置供应商页面配置模型时，先确认该入口的认证机制和用户指定的模型是否兼容；不要自行部署独立代理替代用户指定的配置路径。
- 用户将“完整迁移”进一步限定为“服务器安装最新版、仅同步配置”时，以最新范围为准；不要搬运历史会话与 SQLite 状态，重新建立服务端认证并验证。
- 用户明确 Grok 只负责 ArcReel 文本时，区分纯文本与附图的风格分析；不把图像输入失败误判为纯文本接入失败，也不因模型是文本模型就覆盖图片、视频、音频配置。
- 用户要求 ArcReel 直连 OpenClaw 时，撤销不再需要的 llm-modes-gateway 渠道；在保存凭据前核对 OpenClaw 令牌权限与 ArcReel 数据库存储方式。
