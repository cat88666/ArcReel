# 调试教训

- 服务器版本戳不能证明发布目录与对应 Git 提交逐字一致。基于旧 release 做差量部署时，先对新目录与目标源码做完整文件哈希核验；若发现线上独有的提示词热修，先比对语义并保留有意修改，把例外哈希和发布标识写入记录，避免静默回退角色资产行为。

- 用户要求快速部署时，把构建和验证放在停服之前，停服窗口必须有明确上限。不能关闭网页后无限等待模型生成；先核对 SSE 长连接、任务恢复能力和不可恢复的图片任务，告知中断影响，并按用户最新的恢复服务优先级执行。

- 本项目故障修复不改 ArcReel 代码；用户最终明确允许修改网关、模型、本地 `.env` 和服务器 env。SDK 开关仅在已授权的环境文件中配置；不能把历史请求总 token 当作当前模型固定前缀的实测值。

- 用户报告请求无响应时，原请求自行恢复不等于故障修复。已发现上下文超限、反复压缩与重试，必须继续追踪预算来源、触发阈值和实际计数，在责任层修复并用边界用例验证；将自然恢复与防复发验收分开报告。

- 交付运营手册时，先确认运营的实际内容类型；用户只做小说和剧本 AI 短剧时，以该生产链为主线，不扩写广告、商品或部署教程。

- 提示词契约修复不能等同整条视频链路根治。用户自建 ComfyUI 工作流时，必须把实际提交图、模型家族、编码器/tokenizer、latent/音轨连接及官方提示格式一起核对；只证明新旧图不变，不能证明旧图本来正确。

- 用户要求一次性根因修复时，按上游全部输出格式、素材组合、发声归属和下游全部路由建立契约矩阵；不能以单个成功对白镜头代表覆盖完整。无对白、自由文本附声明、参考语法、能力路由重编译必须分别验证。

- 用户要求先定位解析器时，先确认原文、结构化发声结果和模型实收提示词的边界；未建立责任层证据前，不承诺修复或触发媒体重生成。

- 两行提示词修复也不能无界扩大真实生成矩阵。先估算 GPU 队列与每次实验成本，以用户当前失败片段为主验收；代码测试已通过、有限对照有改善证据时及时收敛，不自动追加跨片/多种子实验。部署状态与媒体质量状态分开报告，不能让排队等待伪装成持续测试。

- 生成原音轨已有异常只能定位到生成端，不能直接推断模型权重缺陷；采样器、参数、运行节点和随机性仍需对照。提示词中的潜在冲突未经单变量验证，不应作为主结论让用户误以为是剧本责任；四步方案应先核对对应作者配置再评价质量。

- 媒体对照样片通过不代表项目当前版本修复。用户反馈新现象时，先锁定当前视频版本、上游 job、实际模型提示词和线上部署状态；字幕抽帧与台词 ASR 分别验收，不能用其中一项替代「动作被朗读」的验证。

- 空上下文 get_context_usage 验证只证明配置传递和计算阈值；不能推导已超限的 resume 历史能自动恢复。用户重启后仍失败时，核对实际 SDK 子进程环境、会话创建时间、失败轮数与压缩事件，区分新会话预防与旧会话恢复。

- 自定义模型窗口不匹配时，先查并实测 SDK 原生 CLAUDE_CODE_MAX_CONTEXT_TOKENS；不能把 AUTO_COMPACT_WINDOW 的最小值当作模型窗口无法下调的证据。通过 get_context_usage 核对 rawMaxTokens、自动压缩状态和阈值后，再判断是否需要源码改造。

- 用户指出提高上下文上限不能解决持续增长时，应先分析每轮新增量、固定工具开销、历史重放与压缩触发条件。扩大容量只能作为临时缓解，不能称为根治；没有增长曲线证据时，不断言指数增长或应用重复注入。

- 用户要求驱动平台测试创作流程时，先排查系统调用与配置，不将任务扩大为代写或生成内容；诊断上下文大小仅提取消息类型、长度、工具 schema 与 token 统计，不读取小说正文。上游 token 超限是症状，取得实际请求构成与计数来源前，不将模型限制差异当作根因。

- 本仓是第三方代码，用户明确要求不改源码。排查错误只在实际责任层调整配置、模型选择、请求适配或网关；不能用应用源码补丁绕过上游故障。本轮误加的源码与测试必须撤回，并让运行服务恢复原版。

- 修改 Agent 凭证后，先区分 HTTP 体检、全新 SDK 请求和已有常驻会话。按 ADR 0017，旧会话保留启动时 env；明确指引用户点击「新建会话」，不要用含糊的「重启会话」让用户误以为刷新或重试能生效。
