# 单 GPU 图片与视频排队分析

## 目标与约束

用户希望图片任务和视频任务分别排队，且不增加服务器资源。尚未选定跨类型的优先级策略。

## 已确认事实（2026-10-12）

- 通过现有 HK SSH 隧道查询，服务器只有一张 RTX 4090 D，显存 24564 MiB；观测时占用 22692 MiB、GPU 利用率 94%。这是瞬时采样，不是所有工作流的峰值测量。
- ComfyUI 0.37.0 的 `main.py:529` 只创建一个 prompt_worker；该 worker 从公共 prompt_queue 逐个取任务执行。
- ArcReel 已按 provider_id 和 media_type 分配独立槽位；本地图片和视频不是共享单槽。
- 网关聊天准入仅作用于 chat/completions；图片、视频最终均提交至同一个 ComfyUI /prompt。
- 不增加资源时，不能保证两个重型工作流同时执行。提高客户端并发或仅改队列名称不能解决服务器串行执行。

## 可选优化

1. 图片优先，保留视频的等待上限或轮转机会，避免视频饥饿。
2. 图片与视频交替执行，同类保持先进先出。

两者都只调整尚未执行任务的顺序，不抢占正在运行的任务，也不能承诺跨类型零等待。必须覆盖同步图片、异步视频、网关重启恢复以及通用工作流，不能只对某个调用入口插队。
