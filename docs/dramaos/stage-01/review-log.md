# Stage 01 审核记录

审核最多三轮 Claude Code；每轮均为只读审核，修复由 Codex 执行。审核日志保留在本机 `/tmp/dramaos-claude-round1.txt`、`round2.txt`、`round3.txt`；以下是可交付的结论摘要。

| 轮次 | 主要反馈 | 处理结果 |
|---|---|---|
| Claude 1：方案 | 取整切点可能错位；MP4 容器需结合扩展名和视频流；ASR、Schema、隐私抽帧、运行上限和验证门槛需写清楚。 | 改为帧索引边界、完整输入门控、可选本地 ASR、Schema 与有限验证。已知硬切样本发现原检测器漏检，方案改用独立 PySceneDetect 依赖组。 |
| Codex：实施 | 默认 CI 可选依赖导入；单帧末尾时长；Schema 错误记录；文档版本与真实产物不符。 | 延迟导入、用视频流真实时长、捕获校验错误并修订文档。 |
| Claude 2：实施 | 默认 CI 收集与 deptry；真实样本可能误提交；无音轨提示、Schema 错误、运行记录描述及 Windows 导入。 | 依赖组映射与检查通过；真实样本目录被 Git 排除；代码与文档修正。 |
| Claude 3：最终只读 | 可变帧率会让切点估算帧号错位；合成证据需用最终代码重跑；未校准字段表述；负 PTS 与末包零时长边界。 | 检测前按帧间时间戳 1% 容差拒绝、补定向用例；两份样本均由最终代码重跑；文档明确 `null` 和剩余拒绝边界。三轮上限已用完。 |
| Codex：最终复审 | 没有新的阻断项；1% 容差也可能拒绝时间基较粗的恒定帧率文件。 | README、方案及风险表使用精确阈值描述，保留该保守边界。 |

最终审核后的快速验证和人工验收边界见 [test-results.md](test-results.md) 与 [acceptance.md](acceptance.md)。
